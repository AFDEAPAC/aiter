# topk_indices_kernel AMD AVO Harness

Generated by `evo_init.py`. Five things to wire before AVO can run unattended;
`validate_evo.py --production-ready` will fail loudly until each is done:

1. `python scripts/query_hw.py > .evo/hw.json`
   captures the SKU, deliverable peaks, and ridge points the agent will cite
   in roofline / efficiency claims for the rest of the run.

2. Replace `bench/correctness.py` with a real fixed-seed reference check.
   The scaffold fails by default until you do.

3. Edit `knowledge/shapes.json` to list the production shape distribution
   (set `enabled: true` on each). This is the canonical shape registry —
   `validate_evo.py` reads it and will reject any score.json whose keys
   don't match.

4. Edit `.evo/config.yaml`'s `shapes:` block to use the same names as
   `knowledge/shapes.json`. The validator cross-checks both and errors on
   drift.

5. Wire `bench/spec.json` only if you use the simple rocprof fallback wrapper:
   set `candidate_argv` / `best_argv` commands, `kernel_name_regex`, `warmup`,
   `repeat`, and `unit` (`us` / `ns` /
   `tflops` / `gbps`). Shape names here must also match #3 / #4. The
   default `bench/run.sh` hands this spec to the rocprofv3 wrapper at
   `scripts/score_from_rocprofv3.py` and emits a higher-is-better
   `score.json`. Production acceptance uses `benchmark_warmup=20` and
   `benchmark_repeat=100`; keep separate rocprof/ATT diagnosis traces small
   with `profile_warmup` / `profile_repeat`.

   Need a hand-written harness? Set `AVO_USE_CUSTOM_HARNESS=1` and
   implement `bench/harness.py` end-to-end (the fallback path).

Then verify and run. Set `CC` to your cursor-config checkout once, so
the commands work from any cwd:

```
export CC=/path/to/cursor-config

python "$CC/skills/agentic-kernel-evolution/scripts/validate_evo.py" . --production-ready
python "$CC/skills/agentic-kernel-evolution/scripts/avo_step.py" . \
    --attempt 1 --hypothesis "first variation" --commit --auto-supervise
```

`--auto-supervise` runs `validate_evo.py --check-stagnation` after each
attempt and prints a `=== SUPERVISOR-NEEDED ===` block when a threshold
from `.evo/config.yaml` `stagnation:` fires. Add
`--fail-on-supervisor-needed` if an outer loop should yield the worker turn
mechanically. The supervisor may append `Decision: continue` or
`Decision: issue_worker_task` / `collect-more-evidence` to
`log/logic_review.md`; rerun with `--require-logic-review` to gate the next
worker step on that decision.
